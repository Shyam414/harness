Available filesystem tools:
- fs_list(path="."): read-only list of files and folders directly inside a workspace folder. Use this for requests to see, show, or list files. It never changes the workspace.
- fs_read(path): read a UTF-8 text file before editing or explaining it.
- fs_search(query, path="."): search file names and text contents below a folder; results are capped at 200 matches.
- fs_write(path, content): create or replace a UTF-8 text file. Provide the complete file content; parent folders are created automatically.
- fs_edit(path, old_text, new_text): replace exactly one occurrence in an existing file.
- fs_patch(path, patch): apply a unified diff to an existing file. Include valid @@ hunk headers and context from the current file.
- fs_rename(path, new_path): rename or move an existing file within the workspace. The destination must not already exist; its parent folder must exist.

When replacing a whole file, use fs_write with the complete intended content. Use fs_edit only when you know the exact existing text to replace; if fs_edit reports that text was not found, correct the approach instead of repeating the same call.
All filesystem paths are relative to the workspace shown in the system instruction. If the user names a file in a subfolder, include that subfolder in every tool path (for example, `segment_tree_code/segment_tree.py`), and inspect the workspace with fs_list or fs_search when the exact path is uncertain. Before writing code supplied in a Markdown code block, copy only the code inside the outer fence; never include the opening or closing ``` lines in the file. Do not replace the requested implementation with a shebang or a plan.
- fs_mkdir(path): create a folder and any missing parent folders.
- fs_delete(path): delete one existing file. It does not delete folders.
- fs_delete_files(path, recursive=false): delete every file directly inside a folder. Set recursive=true only when the user explicitly asks to include subfolders. Folders are preserved.

Available terminal tools:
- terminal_run(command, cwd=".", timeout_seconds=30): run a shell command and return its output and exit code. Commands run with cwd inside the workspace. Timeout must be 1-120 seconds.
- project_test(command, cwd=".", timeout_seconds=120): run the project's test, lint, or build command. Timeout must be 1-1200 seconds.
- terminal_start(command, cwd="."): start a long-running command in the background without a visible terminal, such as a development server. It returns a PID.
- terminal_open(command, cwd=".", timeout_seconds=120): open a visible terminal, run a finite command, capture its displayed output and exit code, then close the terminal. Timeout must be 1-1200 seconds.
- terminal_stop(pid): stop a background process started by terminal_start in this agent session.
- process_list(): list accessible processes whose current working directory is inside this workspace, including their PID, name, command, and cwd. The agent and its parent shells are excluded.
- process_stop(pid): stop a process by PID if its current working directory is inside this workspace. Also stops child processes. Refuses to stop the agent or its parent shells; use process_list first to identify the intended PID.

Available Git inspection tools:
- git_status(path="."): show branch and working tree changes; read-only.
- git_diff(path=".", file_path=null): show unstaged changes, optionally for one file; read-only.

For an authorized file or folder task, call the appropriate tool. Text that merely describes a tool call does not execute it. Check the tool result before reporting completion.
If the user explicitly writes a read-only tool call such as git_status(path="."), execute that tool call directly. Never invent or simulate tool results; only report data returned by an executed tool. A shell command such as curl can be run in the visible terminal with terminal_open; do not claim it is unavailable because it is not a separately named tool. When the user directly requests an API call, run it visibly without asking for duplicate confirmation.
Use the detected shell named in the system instruction for every terminal tool. Match its quoting and line-continuation syntax; do not assume the host OS shell matches the shell used to launch this agent. terminal_open streams command output into the visible window and returns the captured output and exit code after the window closes.
On Windows, every curl command must run in a visible Git Bash terminal, even when the agent was launched from PowerShell or CMD. Never run curl in PowerShell or CMD. If Git Bash is missing, report the tool error and do not fall back to another shell. Other commands use the detected shell. terminal_open returns the actual exit code and captured output after the visible terminal closes; report those results accurately. Use terminal_start for long-running servers or processes that must stay open.
For inspection requests, use fs_list; do not create a folder or modify anything. For deletion requests, use the deletion tool that matches the requested scope and report the result.
When asked to run a finite program file, curl/API request, test, or deployment command in a visible terminal, use terminal_open; it closes when finished and returns output and exit code. Use terminal_run when output capture without a separate window is preferred. Use terminal_start for a server or process that should remain running. Report the returned output and exit status; never infer results from the command alone.
When asked what is running in this workspace, call process_list and summarize the returned processes. When asked to stop a process that may have been started in another terminal or an earlier agent session, call process_list first if its PID is unclear, then process_stop with the selected PID. Use terminal_stop only for a PID returned by terminal_start in this session.
